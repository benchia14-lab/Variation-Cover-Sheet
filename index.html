      The Power Automate connections, and the password on this screen. Password required.

      Office register — section 1 of the cover sheet

      One row per office. Edits are saved to this browser so you can correct a phone number straight away; Export gives you a replacement assets/state-register.js to commit so everyone gets them. The code is what gets matched against the State column in SharePoint, so it must be spelled the same in both.

      Administrator settings

      Power Automate connections, shared by everyone using this app

      Administrator settings

      The Power Automate connections behind this app. Changing them affects everyone using it, so only the administrator gets in.

      Forgotten it? It cannot be recovered — it was never stored. It is reset by replacing assets/settings-password.js and deploying again.

      Treat these URLs as passwords. A Power Automate trigger URL ends in a sig= value, and anyone holding the whole URL can run that flow. They are built into this copy of the app so nobody has to paste them — which also means they are in the page itself, readable by anyone who can open the site. The Microsoft sign-in in front of the app redirects people; it does not stop the file being downloaded. See docs/SIGN-IN.md.
      A

      Power Automate flows

      Asks this site which flows it can run, and tries them. Do this first — the boxes below are only for flows the site is not handling.
        This site holds the flow URLs itself.

        Receives {"state":"VIC"} and answers with the project register rows for that state. Without it the project dropdown stays empty and everything is typed by hand.

        Receives the finished PDF and the project's folder path when someone clicks Download PDF. Without it the PDF still downloads, it just is not filed.

        Receives {"state","projectId","variationRef"}. Without a reference it answers with that project's logged variations; with one, that variation in full. Without this flow the app still works, it just cannot reopen anything.

        Receives the whole variation and creates or updates its row, matched on the project and the variation reference together.

        Optional. Left blank, the "Write professionally" button falls back to a local tidy-up — real sentences and punctuation, but no rewriting.

        Receives {"projectId","folderPath","fileName"} and answers with that file from the project's folder. Saving a variation file needs no flow of its own — it goes through File the PDF. See docs/VARIATION-FILES.md.

        Receives {"projectId","state"} and answers with the Excel file the project register's RatesFile column names. See docs/AGREED-RATES.md.

        What the flow returned

        The first project exactly as Power Automate sent it. If a field you expect is not listed here, or is listed but empty, the flow is not sending it and no setting in this app can change that — the fix is the flow's Select step.

        Match the register columns

        These are the columns your flow returned. The app matches them by name where it can; set any it could not work out. A list built with SharePoint's From Excel import often names its columns field_1, field_2 and so on, which nothing can interpret without being told.

        B

        Build the flow URLs into the app

         

        Takes whatever is in the seven boxes above and gives you back a copy of the app with them inside it. Deploy that, and nobody has to paste anything — it works on every laptop that opens the site.

        Only do this behind a sign-in. A trigger URL's sig= value is the whole authentication, so a copy with them in it hands all seven flows to anyone served the page. That is fine once the site is behind Microsoft sign-in and being served the page already means being in your organisation. It is not fine on an open site, and a filled-in copy should never be committed to a public repository.

          Until that deploy finishes nothing has changed for anyone else. Check it afterwards with Connect to the flows above, on a colleague's laptop rather than your own.

          Password on this screen

           

           

          Now put it live.
          1. The download is a complete copy of this site with the password in it, named index.html.
          2. Netlify → your site → Deploys → drag that index.html onto the drop zone.
          Until that deploy finishes, the live site still has the old password — or none. Keep the password somewhere safe: it cannot be recovered from the file.
          Now put it live.
          1. Find the folder you drag onto Netlify and open its assets folder.
          2. Move the downloaded settings-password.js in there, replacing the one already there.
          3. Netlify → your site → Deploys → drag the whole folder onto the drop zone.
          Until that deploy finishes, the live site still has the old password — or none. Keep the password somewhere safe: it cannot be recovered from the file.
