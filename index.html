Settings

Power Automate endpoints and the per-office letterhead register

Settings is password protected

These are the flow URLs and the office register. Changing them affects everyone using the app, so only the administrator gets in.

Forgotten it? It cannot be recovered — it was never stored. It is reset by replacing assets/settings-password.js and deploying again.

Treat these URLs as passwords. A Power Automate trigger URL ends in a sig= value, and anyone holding the whole URL can run the flow. They are saved in this browser only — never committed to the repository — so each person pastes them once on each device they use.

    What the flow returned

    The first project exactly as Power Automate sent it. If a field you expect is not listed here, or is listed but empty, the flow is not sending it and no setting in this app can change that — the fix is the flow's Select step.

    Match the register columns

    These are the columns your flow returned. The app matches them by name where it can; set any it could not work out. A list built with SharePoint's From Excel import often names its columns field_1, field_2 and so on, which nothing can interpret without being told.

    B

    Office register — section 1

    One row per office. Edits are saved to this browser so you can correct a phone number straight away; Export gives you a replacement assets/state-register.js to commit so everyone gets them. The code is what gets matched against the State column in SharePoint, so it must be spelled the same in both.

    C

    Build the flow URLs into the app

     

    Takes whatever is in the five boxes in section A and gives you back a copy of the app with them inside it. Deploy that, and nobody has to paste anything — it works on every laptop that opens the site.

    Only do this behind a sign-in. A trigger URL's sig= value is the whole authentication, so a copy with them in it hands all five flows to anyone served the page. That is fine once the site is behind Microsoft sign-in and being served the page already means being in your organisation. It is not fine on an open site, and a filled-in copy should never be committed to a public repository.
